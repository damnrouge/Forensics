⚡ What You Need to Know First

Before diving into TrickDump, make sure these ideas are solid. If any feel fuzzy, expand the refresher.

LSASS (Local Security Authority Subsystem Service)
The Windows process that stores credentials in memory (NTLM hashes, Kerberos tickets, sometimes cleartext passwords). Attackers dump its memory to steal credentials. Defenders protect it with PPL, Credential Guard, and heavy monitoring of process handles and memory reads.
Minidump / MiniDumpWriteDump
A structured file format that captures process memory + metadata (modules, threads, system info). The classic Windows API dbghelp!MiniDumpWriteDump creates it. EDRs love hunting for this API call and for files that start with the “MDMP” magic bytes.
NTAPI vs Win32 API
Win32 APIs (kernel32, advapi32…) are high-level wrappers. NTAPIs live in ntdll.dll and talk more directly to the kernel. Many EDRs hook the Win32 layer. Calling pure NTAPIs (or unhooking ntdll first) is a common evasion pattern.
SeDebugPrivilege
A powerful privilege that lets a process open almost any other process (including LSASS) with full access. Must be enabled on the token before many dump techniques work. Token adjustment is a high-signal detection opportunity.
PPL (Protected Process Light)
When LSASS runs as a Protected Process Light, user-mode processes (even as SYSTEM) cannot open it with the rights needed for memory reading. TrickDump (and most user-mode dumpers) fail against PPL.

TrickDump

Dump LSASS memory without ever creating a Minidump file on the target. Split the work, use only NTAPIs, rebuild the dump later.

The Big Picture — Why This Exists

Classic dump tools call MiniDumpWriteDump or write a file that starts with the MDMP signature. Defenders watch for those exact artifacts. TrickDump never produces a valid Minidump on the victim. It produces three tiny JSON metadata files and one ZIP of raw memory pages. The real Minidump is hand-crafted later — usually on the attacker’s machine — by a Python script.

What makes it different

  • • No MiniDumpWriteDump
  • • No “MDMP” file on disk/network
  • • Three separate short-lived processes
  • • Pure NTAPI surface
  • • Optional ntdll unhooking

What still remains detectable

  • • SeDebugPrivilege enablement
  • • Handle to LSASS with VM_READ
  • • High volume of NtReadVirtualMemory
  • • Creation of the three JSON + ZIP files
  • • ntdll section overwrite activity

Deep Dive — The Three Stages

STAGE 1

Lock — OS Information

The simplest stage. It only needs to know the Windows version so the later Minidump’s SystemInfo stream is correct. It calls one NTAPI:

RtlGetVersion → populates RTL_OSVERSIONINFOW (Major, Minor, Build)

Output: lock.json. If you already know the target’s OS build, you can skip this stage entirely.

Why this matters for the final dump

Mimikatz and pypykatz expect a correct SystemInfo stream. Wrong version numbers can cause parsing failures or incorrect architecture assumptions.

STAGE 2

Shock — Modules + Handle

This stage does two critical jobs: obtain a usable handle to LSASS and collect the module list (especially lsasrv.dll) needed for the ModuleList stream.

Exact call sequence (simplified)

  1. 1. NtOpenProcessToken(GetCurrentProcess(), …)
  2. 2. NtAdjustPrivilegesToken(… SeDebugPrivilege …)
  3. 3. Loop NtGetNextProcess → NtQueryInformationProcess until ImageName contains “lsass”
  4. 4. NtQueryInformationProcess + NtReadVirtualMemory to walk PEB → LDR → module list

Why NtGetNextProcess?

Many EDRs specifically watch NtOpenProcess / OpenProcess targeting lsass.exe with high access masks. Walking processes with NtGetNextProcess is less common in detection rules.

Common misconception: “Any handle to LSASS is equally bad.” Reality: the access mask and the API used both matter for detection logic.

Module list purpose

The final Minidump needs at least lsasrv.dll base address and size so tools know where the credential structures live.

Only the modules required for credential parsing are strictly necessary; a full module list is nicer but not mandatory for basic Mimikatz use.

Output: shock.json

STAGE 3

Barrel — Memory Regions

The heavy lifting. With the handle from Shock (or obtained again), it walks every memory region and reads the ones that are committed and readable.

NtQueryVirtualMemory → MEMORY_BASIC_INFORMATION
if (State == MEM_COMMIT && readable) → NtReadVirtualMemory
store raw bytes under a random filename inside barrel.zip
record {filename, base, size} in barrel.json

Result: barrel.json + barrel.zip. The ZIP never contains a Minidump header — just raw page contents with random names.

OFF-TARGET

create_dump.py — Rebuild the Minidump

On the attacker side the three JSONs + ZIP are fed to a Python script that hand-crafts the three streams Mimikatz cares about:

  • SystemInfo — from lock.json
  • ModuleList — from shock.json
  • Memory64List — from barrel.json + the raw pages in barrel.zip
python3 create_dump.py -l lock.json -s shock.json -b barrel.json -z barrel.zip -o lsass.dmp

Optional: ntdll Unhooking

Each binary accepts an argument that overwrites the .text section of the loaded ntdll with a clean copy, bypassing user-mode hooks:

disk

Read clean ntdll from C:\Windows\System32\ntdll.dll (or custom path)

knowndlls

Pull from the KnownDlls section object

debugproc

Start a process in debug mode and copy its clean ntdll

Connections & Synthesis

How it relates to NativeDump

TrickDump is the author’s evolution of NativeDump. NativeDump builds the Minidump on the target (still using only NTAPIs). TrickDump deliberately never builds it on the target, trading some complexity for stronger artifact evasion.

Detection engineering implications

Because the classic dump-file and MiniDumpWriteDump signatures are gone, blue teams must lean on:

  • Sysmon Event ID 10 / Security 4656 — process access to lsass.exe
  • Token privilege adjustment events (SeDebugPrivilege)
  • High-rate NtReadVirtualMemory / NtQueryVirtualMemory against LSASS
  • File creation of *.json + *.zip in the same directory by short-lived processes
  • ntdll .text section modifications or KnownDlls / debug-process patterns

Hard limits

Fails against PPL-protected LSASS. Requires 64-bit binaries. Originally needed a readable PEB (a later branch removes that requirement).
